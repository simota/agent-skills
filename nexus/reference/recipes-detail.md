## Recipe Families (mental model + within-family disambiguation)

Canonical home for the full family taxonomy + within-family axes. SKILL.md `### Recipe Families` keeps a compact grouping + one-line axis; this table carries the full axis prose and the overloaded-anchor REDIRECT escalations. The Recipes table below (and in SKILL.md) is flat; these families group it and name the axis that separates confusable siblings. **When an input fits a family but not a specific recipe, use the axis to pick — or, for an overloaded anchor, run the one-question REDIRECT (`reference/intent-clarification.md`).**

| Family | Recipes | Distinguishing axis within the family |
|--------|---------|----------------------------------------|
| **Fix** | `bug` · `security` | fault class: defect vs vulnerability |
| **Improve** (existing code) | `refactor` · `optimize` · `kaizen` · `anneal` · `restyle` | refactor = apply a *known* internal restructure (known scope) · optimize = perf-only (a number) on *correct* code — a slowdown caused by a defect (wrong output, memory leak, regression from a change) is `bug`/`+Trail`, not `optimize` · kaizen = multi-axis polish of *one feature* vs a known target · **anneal = *discover* undiagnosed design weaknesses across a scope → brush up the prioritized slate, behavior-preserving** · **restyle = improve the *visible* design (UI · visual · interaction) of an existing surface, direction+rubric-driven, behavior-preserving**. **`improve`/`polish`/`enhance` is overloaded across all five → REDIRECT** (`audit the design` / `brush up the codebase` / `harden the architecture` → `anneal`; `improve a feature vs a target` → `kaizen`; `known single restructure` → `refactor`; `iterate to a quality bar` → `converge` in the **Loop** family; `redesign` / `UI refresh` / `look and feel` → `restyle`). **`improve the design` alone is overloaded on the code-vs-visual axis → REDIRECT** (architecture/code design → `anneal`; UI/visual/look-and-feel → `restyle`). **Upstream of `anneal` sits `assay` (Quality-Max)**: `anneal` discovers *weaknesses* and fixes them; `assay` proves or refutes the codebase's stated design *claims* by executed experiment and hands `anneal` a pre-evidenced slate — **prove vs fix**. Route to `assay` only when the *stated* design is what is in question ("is this actually a good design", "is this abstraction necessary", "do the layering rules hold"); a plain "the design has drifted, clean it up" stays on `anneal`, which is the cheaper default. |
| **Loop** (autonomous / iterative execution) | `goal` · `converge` | goal = native `/goal` *setup only* (no run) · converge = in-session rubric Generator-Evaluator quality loop. **Every loop passes `_common/LOOP_PRECONDITIONS.md` first** — its § Shape resolution classifies an underspecified `make a loop`/`automate with a loop`/`run until done` to the right owner, gating on the loop-engineering preconditions (verifiable oracle · external hard-stop · maker≠checker · persistent memory · drift-aware). **The unattended runner is the `orbit` skill** — never re-implemented here; discovery→ship loop → `apex`. An explicit shape → the sibling direct. |
| **Build** (new) | `feature` · `apex` | feature = single guided build · apex = general discovery→ship one-shot (8-25 agents) |
| **Discover → build pairs** | `spec`→`feature`/`apex` · `charter`→`enact` · `layer`→`sigil`-authoring | spec = one feature *spec* (dialogue) · charter = whole-repo *team + work plan* · layer = whole-repo *reusable operating layer* (project skills + recipes + workflows + routing map). All stop at a design; the pair runs it. **`layer` vs `charter`**: charter plans *what work to do + who does it* (one delivery); layer designs *what reusable tooling the repo should have* (persists). **`layer` vs `sigil`**: layer designs the coordinated *set* (Loom), sigil authors *one* skill body. |
| **Reason** (no code) | `gedanken` · `delve` | output = insight, not a build. **gedanken** = abstract thought-experiment about a claim/hypothesis (construct→reason→perturb→refute→conclude); **delve** = grounded deep-dive into a *shipped* feature → evolution directions (deepen/broaden/reframe). Axis: abstract-hypothetical vs grounded-existing-feature. Both orchestrate `magi`/`flux`; trivial "what if" → `flux`/`magi`, trivial "what could we do with X" → `riff`/`spark` direct. **`gedanken` vs `magi`** (intent-anchored, not keyword-anchored — "worth it" alone doesn't decide it): verdict-seeking (wants a final go/no-go delivered) → `magi` direct; process-oriented (wants the reasoning walked through — e.g. "think through whether microservices are worth it here, no code") → `gedanken`. **`delve` vs `kaizen`** (discover directions vs execute vs a target): `evolve`/`improve a feature` is overloaded → REDIRECT. |
| **Comprehend** (reverse-engineer existing code → understanding artifact, no code) | `cartograph` · `chronicle` | output = a grounded documentation artifact of *what exists*, not insight/evolution and not a build. **Within-family axis: space vs time.** **cartograph** = reverse-engineer a feature/system **across multiple repos** from the code → **bird's-eye architecture diagrams + design document** (scope→map-per-repo→correlate-seams→synthesize→diagram→document→ground-verify); a **spatial-structure snapshot** of how it works *today*, grounded in **code citations**. **chronicle** = reverse-engineer a repo's **commit history** → **era timeline + narrative storylines + lens deep-dive files (security/domain-design/architecture/performance/design-ux/issues, split per file) + inferred ethos + history document set** along **two axes** — time (**eras**) × theme (**storylines**: feature-lineage · defect-&-resilience · improvement · **decisions** → reconstructed ADR-style decision log) — then **DISTILL** infers the project's **ethos/worldview** (design philosophy · value hierarchy · conventions · product thesis) from the *patterns* (scope→survey→segment-2-axis→excavate-turning-points+thread-beats→synthesize-weave→deepen-lenses→distill-ethos→diagram→document-split→ground-verify); a **temporal-evolution arc** of how it *got here* **& what it believes**, grounded in **commit SHAs** (ethos tenets pattern-grounded + refutation-gated, labeled inferred), people-neutral (no rankings). Axis vs the Reason family: **document-what-exists/how-it-evolved** (backward, comprehension) vs **reason/evolve** (forward). vs `delve` (one shipped feature, dialogue, evolution directions) · `charter` (one repo → team+work plan) · `pdm` (plan-vs-code status) · `clone` (black-box external → *rebuild*). Single repo / one diagram → `lens`/`atlas`/`canvas` direct; one period's PR report → `harvest` direct; one diff to teach → `tome` direct; one archaeology question → `trail` direct (minimum viable chain). |
| **Verdict** (which feature) | `essential` · `killer` · `trim` | essential = THE must-have · killer = THE differentiator · trim = remove dead-weight (inverse). Shared gate: `reference/verdict-gate.md`. |
| **Reproduce, Synthesize & Invent** | `clone` · `fuse` · `graft` · `transmute` · `migrate` · `eureka` | source count/fidelity: clone = 1 source faithful · fuse = ≥2 sources synthesized · graft = host+donor *concept* (rejects surface copy) · transmute = own-source cross-language · migrate = own-system change-completeness · **eureka = zero sources — originates a mechanism and *proves* it novel against a Prior-Art Ledger; a collision with an existing source kills the candidate rather than feeding it**. Shared discipline: `_common/DIFFERENTIAL_PARITY.md`. **`differential parity` alone is ambiguous → REDIRECT.** |
| **Quality-Max** (expensive, confirm) | `acceptance` · `growth-acceptance` · `summit` · `podium` · `wish` · `runway` · `crucible` · `silhouette` · `lattice` · `chorus` · `assay` · `hallmark` · `rebrand` · `marquee` | acceptance = proof-carrying merge (G1-10) · growth-acceptance = post-launch lifecycle (G11-15) · summit = pre-merge quality tournament · podium = content/slide quality · **wish = once-in-a-lifetime one-shot ceiling: scarcity-gated, deliverable-agnostic wrapper — crystallization dialogue + exemplar-sourced ceiling anchors + cross-engine blind tournament + adversarial gauntlet + ceiling convergence on calibrated evaluators (ACCEPT = all rubric dims = 3) + reception simulation + One-Shot & Comparative exit gates, inside a declared budget envelope. Axis vs siblings: summit = *engine triangulation for strategic code*; converge (Loop family) = *standard bar, all dims ≥ 2, revisions expected*; wish = *the single most important ask, no second delivery*.** **Design/brand wing:** runway = flagship *in-product UI surface* design tournament (3 directions → ceiling, all dims = 3) · hallmark = *create* the brand identity (proof-carrying Brand Book) · rebrand = *propagate* a settled brand across all surfaces (completeness-proven, RESIDUE-GATE) · marquee = wish-grade one-shot *acquisition LP* (machine oracles Lighthouse/CWV/WCAG; **no Scarcity Gate — intentional vs wish**). **The design wing asks one question per recipe, each with its own oracle:** *is it the best?* → `runway` (rubric ceiling) · *does it work at all?* → **`crucible`** (binary task completion per condition cell — the **floor**; `runway` and `crucible` are orthogonal and commonly sequential: ceiling first, floor proven after) · *is it recognizably ours?* → **`silhouette`** (blind attribution rate vs K competitors, measured against a **pre-committed** Sameness Ledger, with distinctiveness forbidden from costing usability) · *is it one system?* → **`lattice`** (steady-state token/component conformance; RESIDUE-GATE to dry, three-way `residue`/`gap`/`justified` classification, appearance parity as the safety oracle) · *is it one product across platforms?* → **`chorus`** (Idiom Gate × Kinship Gate as two measurements of one ratified Invariant/Variant Contract) · *what is the brand?* → `hallmark` · *did the brand land everywhere?* → `rebrand`. Axes: `runway` vs `marquee` = in-product surface vs conversion-driven LP; `lattice` vs `rebrand` = steady-state conformance vs identity migration (same RESIDUE-GATE machinery, different denominator); `lattice` vs `chorus` = within one platform's system vs between platform systems (compose: `lattice` ×N, then `chorus`); `crucible` vs `siege` skill = the interface vs the system behind it; `silhouette` vs `hallmark` = the product surface vs the brand identity (silhouette *consumes* a settled identity as its derivation source); `hallmark` → `rebrand` = create→propagate pair (a discover→build pair living in this family for its cost/gates); `port` skill → `chorus` = plan→prove pair. **The code-design wing has one member:** *are the design claims true?* → **`assay`** — the same "prove, don't judge" move applied to code/architecture: harvest the codebase's load-bearing design claims (ADRs · docs · stated conventions · **what the structure implicitly claims** · the roadmap), freeze them as a denominator, and resolve each by an **executed experiment** (`ADD`/`SUBTRACT`/`REWRITE`/`ASSERT`) under a single oracle — zero `UNPROVEN` claims, with `REFUTED` counting as resolved. `assay`(prove) → `anneal`(fix) is a **measure→fix pair** spanning this family and **Improve**; `anneal` alone stays the cheaper default when the ask is "find what's wrong" rather than "prove what we claim". |
| **Grounded content** | `newsroom` | output = an article whose every factual claim is provenance-proven. **newsroom** = claim-grounding maximization for a single written artifact: Evidence Ledger (per `reference/research-grounding.md`, primary-source-authoritative) built *before* writing (compose) or against an existing draft (audit) → producer≠verifier claim audit with **citation-support re-open** → adversarial refutation of load-bearing claims (≥2 independent T1–T3 sources) + staleness check → remediation ≤2 cycles → named **Provenance Report**; unresolvable claims marked `[UNVERIFIED]`, never silently kept or deleted. Axis vs neighbors: `podium` = package *polish* across formats (grounding is one Phase 4 branch there — newsroom inverts the weighting: grounding IS the deliverable); `zine` direct = authoring with no grounding requirement; `attest` = impl-vs-*spec* (newsroom is prose-vs-*world*); `canon` = named-standards compliance. |
| **Document package** | `package` (incl. `venture`) | 12-domain preset registry |
| **Meta / control** | `classify` · `proactive` · `pack` | routing · project scan · skill-profile |

## kaizen

Existing-feature continuous improvement covering perf / UX / code-quality / feature-extension. **PDCA loop, not single-pass**: improves against a quantified target and stops on target-met or diminishing-returns. Differs from `refactor` (internal-only), `optimize` (perf-only), and `feature` (new addition). Scale: 4-8 agents (× ≤3 cycles).

**Chain template:**
`(Lens + Pulse?/Echo?/Voice?/Trace?)[baseline] → Spark → Magi[axes + target + stop] → ⟲{ (Bolt/Tuner ‖ Palette/Prose/Flow ‖ Zen/Sweep ‖ Artisan/Builder)[axis] → Radar[+cross-axis guard] → Pulse?/Echo?[re-measure vs target] }⟲ → Void[stop-confirm] → Guardian`

The `⟲{…}⟲` block loops until target-met OR diminishing-returns OR iteration cap. Full phase contract (DIAGNOSE+BASELINE / PROPOSE+TARGET / IMPROVE / VERIFY+LOOP / SHIP) → `reference/inline-recipes.md`.

## anneal

**Codebase design audit → prioritized behavior-preserving brush-up.** The corrective, execution-bearing member of the Improve family: where `kaizen` improves *one feature against a target you already chose*, `anneal` **discovers undiagnosed design weaknesses across a scope you have not pre-diagnosed, then brushes up the prioritized slate**. Surface design issues from six independent dimensions (architecture / code-smell / standards / over-engineering / under-specified design = edge cases & invariants / **specification = spec↔code conformance & drift, AC traceability, undocumented behavior**), prioritize by value × risk, and fix the slate with real code that **preserves behavior** (refactor-grade discipline) — gated by a dual VERIFY (no-regression + Before/After design-metric proof). The metallurgical metaphor: relieve accumulated internal *design stress* and leave the structure tougher, not cosmetic polish. `<target>` scopes the audit; **no target → whole-codebase sweep** (confirm-before-launch, slate capped to top-N by value × risk, long-tail recorded). Default Mode `AUTORUN` with the Phase 3 slate gate (Ask First on 10+ files / `PUBLIC_API` / `DATA` / any `behavior-changing` fix). Named **Design Ledger**; checkpoint-resume (`anneal resume`). Engine routing follows summit principles (Codex code-gen / Claude judgment). Distinct from `refactor` (known restructure, known scope), `optimize` (perf number), `kaizen` (one feature vs known target), `delve` (no code — evolution directions), `trim` (remove features), `summit`/`acceptance` (PR-gated), and the spec-axis neighbors `spec` (author a *new* spec) / `attest`·`pdm` (report-only conformance) / `acceptance` (PR gate). 6-16 agents × ≤3 cycles, medium-to-high cost (cost scales with slate size, not codebase size — PRIORITIZE is the governor).

**Chain template:**
`MAP (Lens[map design] + Atlas[deps/layering/God-class/boundaries] +Grove?/Trail?) → ✓scope-gate (confirm-before-launch when no-target/structural) → CRITIQUE (Atlas[architecture] ‖ Zen[code smells] ‖ Canon[standards/ISO-25010] ‖ Void[over-engineering/YAGNI] ‖ Omen[under-specified/edge-cases/invariants] ‖ Attest/PDM[spec: spec↔code drift/AC traceability/undocumented behavior] +Gateway?/Schema?/Sentinel?; → evidence-tied Design-Issue Ledger; false-positive filter + skeptic pass per _common/ADVERSARIAL_REFUTATION.md) → PRIORITIZE (Ripple[blast-radius] + Rank[value×risk×effort] + Magi[slate; defer long-tail; flag behavior-changing]) → ✓slate-gate → BRUSH-UP [Radar safety-net green-before → ⟲{ (Atlas+Builder ‖ Zen ‖ Void+Sweep ‖ Gateway+Builder ‖ Schema+Builder ‖ Accord/Scribe+Radar[spec: update stale spec / lock undocumented behavior; code-conformance → flag behavior-changing]) per _common/PARALLEL.md → re-critique touched area }⟲ loop ≤3 cycles (default 3): ACCEPT | diminishing-returns (Δ<ε) | cap-reached | BLOCK ] → VERIFY (Radar[regression same-suite-same-result] + Atlas/Canon/Attest[Before/After design + spec-drift metrics] + cross-axis guard + Judge[multi-engine diff review]) → SHIP (Guardian[phased small-scope commits + Design Ledger + ADRs])`

Full phase contract (MAP / CRITIQUE / PRIORITIZE / BRUSH-UP / VERIFY / SHIP), Failure Modes Prevented, and boundaries → `reference/anneal-recipe.md`. Wrap in a rubric-graded loop via `converge anneal`.

## restyle

**UI/visual design improvement of an existing surface** — the UI/visual-design member of the Improve family: where `anneal` improves *code* design and `kaizen` improves *one feature* against a quantified metric, `restyle` improves the **visible design itself** (look · feel · motion · hierarchy · consistency) of a screen / component / flow. Audit the current design (Echo persona walkthrough + friction baseline ‖ Palette heuristics + a11y baseline), have Vision set a **design direction + Design Brief** (rubric axes with current→target scores + explicit non-goals), confirm at the ✓direction-gate, then loop implement↔verify against the Brief — verified by Echo re-walkthrough, **a11y ≥ baseline**, and a Radar no-regression gate (restyle changes presentation, never contracts). Muse's **token-first rule** (tokenize before ad-hoc styles) makes each restyle strengthen the design system instead of eroding it. `<target>` scopes the audit; **no target → whole-UI sweep** (Confirm-before-launch; slate capped to top-N by friction × visibility, long-tail recorded). Default Mode `AUTORUN` with the ✓direction-gate (Confirm-before-launch on no-target / full-surface / brand-token / 10+ files). Named **Lookbook**; checkpoint-resume (`restyle resume`). Engine routing follows summit principles (Codex code-gen: Artisan/Flow/Muse-apply/Ink; Claude judgment: Echo/Palette/Vision/Guardian). Distinct from `kaizen` (one feature vs a metric target — a kaizen UX axis that grows into a redesign hands off here), `anneal` (code/architecture design), `feature` (new capability), `vision` direct (direction only, no execution), `palette`/`flow`/`muse` direct (one named fix — minimum viable chain), the `atelier` skill (full design-to-impl pipeline incl. prototypes/assets/persistent design system — hand off when scope becomes pipeline-wide), `bazaar` (LP studio). 5-12 agents × ≤3 cycles, medium cost (slate cap is the governor).

**Chain template:**
`AUDIT (Echo[walkthrough+friction baseline] ‖ Palette[heuristics+a11y baseline] +Frame?/Muse?[token-drift]/Voice?/Trace?) → DIRECT (Vision[direction + Design Brief rubric] +Flux?[reframe premise]) → ✓direction-gate → ⟲{ IMPLEMENT (Artisan ‖ Flow? ‖ Prose? ‖ Muse?[token-first] ‖ Ink?) → VERIFY (Echo[re-walk vs rubric] + Palette[a11y ≥ baseline] + Radar[no-regression]) }⟲ loop ≤3 cycles (default 3): ACCEPT | diminishing-returns (Δ<ε) | cap-reached | BLOCK → SHIP (Guardian[phased commits + Lookbook])`

Full phase contract, Failure Modes Prevented, boundaries + Decision Tree → `reference/restyle-recipe.md`. Loop discipline per `reference/evaluator-loop-protocol.md` (Brief = rubric; Echo/Palette = independent Evaluators).

## apex

Full-cycle auto-implementation: discovery → spec → parallel design → risk gate → loop → ship. With no-args, Phase 0 autonomously discovers the goal. 8-25 agents, high-cost. **Confirm before launch.**

**Chain template:**
`(Phase 0 if no goal) → Discovery (plea+field+echo?) → Ideate (riff) → Verdict (magi) → Spec (accord+void?+scribe?) → Design [Tech (atlas+gateway?+schema?) ‖ UX (Vision sub-orchestrates muse+palette+prose+flow?+frame?+forge+echo)] → Risk Gate (omen+ripple+echo) → Loop (Orbit on Codex CLI drives builder+artisan?+vitrine?+judge+radar+voyager?) → Acceptance Verification (attest: AC-conformance gate) → Ship (guardian+launch)`

Guarded by a run-level budget envelope (hard-abort at ceiling) + cross-phase checkpoint-resume. `attest` gates Ship on accord's L3 ACs (convergence ≠ correctness).

Read: `reference/apex-recipe.md`, `reference/apex-walkthrough.md`.

## charter

**Repo-wide analysis → self-driving Charter, team design included — stops at the document.** Document-first planning recipe; the execution half is `enact`. Where `apex` discovers a *feature* and ships it in one shot, `charter` reads the *whole repository*, distills a durable Charter artifact (`docs/CHARTER.md` + `CHARTER.roster.yaml`) that designs the team (§5 roster + §6 orchestration plan) and §10 checklists (pre-flight / per-package Definition-of-Done / progress tracker / final delivery) without building or running it. The team becomes a pure function of the document, so `enact` (or a future session) reconstructs the identical team and gates each boundary on the checklists. Distinct from `apex` (feature-centric, one-shot), `goal` (loop config only), `package` (docs only). The §5/§6 design is **multi-engine by default** (`engines=claude+codex`): Claude Code for plan/design/review, Codex CLI (model `gpt-5.6-terra`, C3.0 variant tiering) for build loops + high-volume parallel coding (Orbit sub-hub pinned to Codex, per-engine prereqs + `fallback_engine` recorded for `enact`). Modes: autonomous (no-args) / objective-supplied / `scope=` / `out=` / `engines=`. 5-15 agents (analysis + authoring only). No execution → no Confirm Gate.

**Chain template:**
`Phase 0 Framing → 1 Comprehensive Analysis (lens ‖ atlas ‖ grove? ‖ trail? ‖ sentinel?/canon?/sweep?/pulse?) → 2 Objective+WBS (spark+rank? → sherpa → accord + magi?/omen?/ripple?) → 3 Charter Authoring incl. team design (scribe +accord trace, void? → finalize §5 roster + §6 plan → write docs/CHARTER.md + roster.yaml) → DELIVER (recommend /nexus enact)`

Read: `reference/charter-recipe.md`.

## enact

**Execute a Charter end-to-end.** The execution half of the `charter → enact` pair: reads an existing Charter, **constructs the team from §5 roster** (bind role→skill→spawn + verify prereqs), **orchestrates §4 work breakdown** via the §6 plan (spawn per package; Orbit sub-loop for build iterations; checkpoints + guardrails; hub-spoke aggregate), then verifies §7 and ships. Updates §9 Execution Log so the Charter stays the living source of truth; `resume` restarts from the last checkpoint. No analysis/planning — the Charter is the complete contract; a missing/invalid section stops at Phase 1 rather than improvising. **Runs to completion (enforced under AUTORUN_FULL):** no mid-run stops for progress, recoverable failures (retry→fallback_engine→Scout+Builder→alt owner→`SKIPPED(blocked)`+continue), or cost; loops until every §4 package is terminal (SUCCESS/PARTIAL/SKIPPED). Only intentional stops = §8 safety red lines (L4/destructive/out-of-scope) + no-valid-Charter precondition. Honesty preserved: §7 failures delivered truthfully, not masked. **The orchestrator streams every progress event to an append-only run-log file** (`docs/CHARTER.run.log.md`, override `log=`); Charter §9 holds only a pointer + summary, and `resume` restarts from the run-log tail. ★ Gate is announce-and-proceed (no objection window); GUIDED/INTERACTIVE re-introduce stops. Modes: `enact <path>` (default `docs/CHARTER.md`) / `dry-run` (construct + verify only) / `resume`. 6-30+ agents.

**Chain template:**
`read Charter (validate §3-§8) → Phase 1 Team Construction (bind role→skill→spawn, verify prereqs, sub-orch setup, dry-run check) → ★ Confirm → Phase 2 End-to-End Orchestration (spawn per §4 package in §6 order; orbit sub-loop; parallel + file ownership; append §9) → Phase 3 Verify+Deliver (radar?/judge? → §7 gates → guardian?/launch? → update Charter §9)`

Read: `reference/enact-recipe.md`.

## layer

**Design + stand up a repo's operating layer — Loom designs, Sigil authors, Nexus registers.** The Nexus surface over the **Loom** agent (project-scoped analogue of Architect). Where `charter` designs a *team + work plan* to deliver a body of work, `layer` designs the *reusable operating layer* a repository should carry: which project-local skills encode its conventions, which repo-tailored recipes chain them, which skill-and-agent workflows coordinate project outcomes, and a routing map (single-owner per task domain; ecosystem-owned tasks deferred, never duplicated). Loom **designs the system and delegates the threads** — it never writes a skill body, runs a chain, or authors a hook: Loom blueprints, Sigil authors each body (9+/12), Nexus registers recipes/workflows/routing map, Latch/Orbit take hooks/loops. Mechanism choice per task uses `_common/MECHANISM_SELECTION.md` for hook/rule/subagent/skill; `recipe`/`workflow` are Loom-local. Each designed workflow carries a formal topology + `≤ 5` phases (no Bag-of-Agents). Distinct from `charter` (team+work plan, one delivery), `sigil`/SKILL_GEN (one skill body), `spec` (one feature spec). Modes: whole-repo (no-args) / `<scope>` / `design-only` (stop at the blueprint, charter-style) / `resume` / `engines=`. **Confirm-before-launch** (DELEGATE writes files + changes routing); `≥10` skills or established-routing changes → Ask First. Named report: **Operating-Layer Blueprint** (+ Layer Report tail in full mode). Checkpoint-resume (`layer resume`). 5-15 agents (design-only 3-6); Low-Medium cost.

**Chain template:**
`Phase 0 Frame (detect repo/stack/scope/existing-layer/mode) → 1 Survey (loom drives ‖ lens(structure) ‖ atlas?(arch→topology) + read .claude/ layer + sigil inventory?; greenfield→infer from manifests/CI/history) → 2 Design (loom: coverage matrix + suite plan + recipes + workflows[topology,≤5] + routing map) → 3 ★Confirm blueprint (design-only stops here) → 4 Delegate (parallel: sigil×N author bodies 9+/12 ‖ latch hooks ‖ orbit loop specs → nexus registers recipes/workflows/routing map ‖ grove docs placement) → 5 Verify (loom 14-item + sigil 9+/12 + routing single-owner + workflow topology/≤5) → DELIVER Layer Report`

Read: `reference/layer-recipe.md`.

## spec

**Interactive feature-proposal → locked specification through deep human-in-the-loop dialogue.** Takes a rough idea and refines it conversationally into a sign-off-ready spec carrying **mandatory testable, traceable acceptance criteria**, then **stops at the spec — writes no code**. The discovery half of `spec → feature`/`apex`, mirroring `charter → enact`. **Defaults to `INTERACTIVE`** (with `delve`; the dialogue is the deliverable); its phase-boundary checkpoints are contract-level, so even AUTORUN cannot skip them. **+Lens reuse-scan grounds it in the existing codebase; draft-persisted & resumable** (`spec resume [<slug>]`); locks only when **all lock preconditions pass — testable L3 ACs + the Spec Quality Gate** (ambiguity/completeness/consistency/testability/scope/provenance) **+ a refute-polarity skeptic panel** on the four load-bearing claims (problem-real / direction-beats-rejected / ACs-entail-REQs / scope-separable, `_common/ADVERSARIAL_REFUTATION.md`) — and writes `docs/specs/<slug>.md` per a standard template; the dialogue itself is conducted per `reference/dialogue-protocol.md` (question craft, Assumption Ledger, Provenance Gate). **Depth-scaled** (`depth=light|standard|deep` — scales turns and panel size, never the lock preconditions) and emits a **Spec Handoff Packet** (ACs + non-goals + assumption ledger + refutation flags + reuse findings) the build recipes consume without re-deriving. Distinct from `essential`/`killer` (which-feature *verdict*, minimal dialogue), `feature`/`apex` (build code), `charter` (whole-repo team design), `converge` (automated grading loop), and `riff` (single-agent brainstorm, no artifact). 3-12 agents × dialogue turns (light 3-5 / standard 5-9 / deep 8-12).

**Chain template:**

## gedanken

## cartograph

## chronicle

Excavate the **turning-point commits + thread beats**, synthesize the **overall arc + per-storyline mini-arcs** (first commit → HEAD), and produce a **history document set** (`docs/history/<slug>/`): a `README.md` overview with era-timeline, storyline swimlanes/matrix, decision log, and a lens index — plus a **DEEPEN** phase that re-reads the history through the default **deep-dive lenses** (security · domain-design · architecture · performance · design-ux · issues), each written to its **own split file** (`lenses/<lens>.md`: era-by-era evolution · cited key-commit ledger · current state · open risks; empty lens → absent stub, never padded; capped ≤ top-K commits per lens per era, EXCAVATE overlaps reused; `lenses=…` narrows, `lenses=none` → legacy single `docs/history/<slug>.md`). The story is the **weave**: eras are the *acts*, storylines are the *plot lines*, and the ethos is *who the project turned out to be* — not a flat log, not just a phase list. Distinct from `cartograph` (spatial structure snapshot — chronicle is the temporal arc), `harvest` (one *period's* PR report — chronicle reads the *whole* history into eras+storylines+arc and *uses* harvest as its SURVEY engine), `tome` (one *diff* → teaching doc — a turning-point/thread-beat engine inside chronicle), `trail` (one *regression/archaeology question* — whole-history synthesis is chronicle), `atlas` (authors a *forward* ADR for a live decision — chronicle *reconstructs past* decisions from history), `magi` (deliberates a *live decision* — chronicle-DISTILL infers a *descriptive ethos* from history, decides nothing), `delve` (one feature → evolution *dialogue*, no docs), `charter` (repo → team+work plan — chronicle documents the past, not the plan), `pdm` (plan-vs-code present status). ## newsroom

Two modes: **compose** (evidence-first — the Evidence Ledger per `reference/research-grounding.md` is built *before* writing and the writer is ledger-bound) and **audit** (existing article → claim-driven sweep → correction). Core guarantees: **citation-support over citation-existence** (the auditor re-opens every cited source and confirms it states the claim), **producer ≠ verifier** (auditor/skeptics never the writer, Q9), **corroboration** (load-bearing facts need ≥2 independent T1–T3 sources; T4 never sufficient alone), **staleness check** vs publication date, and **never-silent** (unresolvable claims ship marked `[UNVERIFIED]` or are deleted with a log — silent keep and silent delete both forbidden). Named **Provenance Report**; checkpoint-resume (`newsroom resume`). 6-16 agents × ≤2 remediation cycles, 2-5× cost. **Confirm release-critical** (conditional — intentional parity with podium). Distinct from `podium` (package polish across formats — grounding is one branch there; newsroom inverts the weighting), `zine` direct (authoring, no grounding requirement), `attest` (impl-vs-spec; newsroom is prose-vs-world), `canon` (named-standards compliance), `clone`/`fuse`/`graft` sweeps (same ledger machinery, capture-authoritative vs newsroom's primary-source-authoritative).

**Chain template:**
`Phase 0 Framing (mode + risk_tier + claim-tolerance contract + load-bearing thesis; release-critical → ✓confirm) → 1 Evidence Sweep (Field ‖ Lens/Harvest? ‖ Compete?; Research Completeness gate) → 2 Compose (Zine+Prose?, ledger-bound) [compose mode only] → 3 Claim Audit (spawned auditor ≠ writer: taxonomy fact/inference/opinion/speculation + citation-support re-open → claim_audit.json, no claim absent) → 4 Adversarial Verify (skeptic ×2-3 per _common/ADVERSARIAL_REFUTATION.md ‖ staleness) → 5 Remediate loop ≤ 2 cycles (exit: ACCEPT | cap-reached | BLOCK on refuted thesis) → 6 Deliver (Provenance Report)`

## wish

**Once-in-a-lifetime request** — scarcity-gated **one-shot quality-ceiling** delivery, deliverable-agnostic (code / document / design / content / plan). Seven identity elements no sibling carries together: **Scarcity Gate** (usage journaled in `.agents/nexus.md`; routine invocations challenged — anti-inflation is contract-level), **Benchmark Anchor** (score-3 descriptors *sourced* from best-in-class exemplars via a cited Evidence Ledger, user-ratified before the rubric freezes — a ceiling invented by the system that must reach it is not a ceiling), **Ceiling ACCEPT** (all rubric dims **= 3**, raised from converge's ≥ 2), **calibrated evaluation** (two-point calibration against the exemplar and a routine-quality control; an uncalibrated evaluator cannot produce a ceiling ACCEPT), **Wish Crystallization** (contract-level dialogue excavating the true wish + *disappointment criteria* + the named recipients), **cross-engine blind tournament** (3-5 candidates distributed across model families, one per (engine, angle), provenance stripped until scores are recorded; dual-lineage carry on L/XL), and a **two-part exit gate** — **One-Shot Gate** (fresh-context verifier: "would a redo be materially better?" with cited evidence) **+ Comparative Gate** (blind head-to-head vs the exemplar and vs our own retained runner-up; a loss to the runner-up means convergence destroyed value). Also carries a **Reception Simulation** (named recipients meet the artifact cold), a **bounded rubric amendment** (once, user-ratified), a **budget envelope** (`budget-reached` delivers best-so-far, never a silent overrun), and an **Unexplored-Space Ledger** (what was deliberately not pursued). 27-102 agents × ≤5 cycles (+1 bonus), 10-28× cost. **Always confirm** (the Scarcity Gate is the confirmation; intentional parity with summit's unconditional gate). Distinct from `summit` (multi-engine tournament for strategic *code*), `converge` (standard bar, revisions expected), `apex` (build lifecycle), `podium` (content pipeline).

**Chain template:**
`Phase 0 Scarcity Gate ★confirm-before-launch (Wish Ledger + outcome backfill + budget envelope + cycle cap + 2-of-3 routine-task challenge) → 1 Crystallize ★contract-level dialogue (Wish Contract incl. named recipients + draft Ceiling Rubric: 3-5 dims, task-specific score-3 anchors; disappointment criteria as score-0 triggers) → 1.5 Benchmark Anchor ★contract-level ratification (deep-research sweep per reference/research-grounding.md → exemplar set 2-4 + routine-quality control → score-3 anchors rewritten as SOURCED → rubric freezes, envelope restated; no exemplar found → declared fallback to invented anchors + Magi/Omen reachability check) → 2 Tournament (3-5 candidates CROSS-ENGINE, one per (engine, angle), outline-level for S/M scope ‖ → two-point CALIBRATION pass on exemplar+control → BLIND judge panel, provenance revealed after scoring → winner + retained runner-up + salvage list) → 3 Gauntlet-Converge ≤3 cycles (≤5 on L/XL within envelope) (calibrated independent Evaluators per dim ‖ dual-lineage carry through cycles 1-2 on L/XL → lineage merge gate ‖ staged refutation panel per _common/ADVERSARIAL_REFUTATION.md once all dims ≥ 2; ≤1 user-ratified rubric amendment; Omen pre-mortem near ceiling; dims = 3 → candidate ACCEPT → panel ratifies) → 3.5 Reception Simulation (Cast/Echo/Plea as the named recipients, cold, no rubric → evidence on existing dims, never a parallel gate) → 4 Exit Gates (One-Shot: fresh-context redo-verdict with cited evidence ‖ Comparative: blind head-to-head vs exemplar and vs our own runner-up; together ≤1 bonus cycle, re-gate advisory-only) → 5 Deliver (Fulfillment Report + Unexplored-Space Ledger + Wish Ledger append)`

## crucible

**Operability proof under adversarial conditions** — the **floor** member of the Quality-Max design wing, and the only design recipe whose oracle is **binary rather than scored**: every cell of a (critical task × condition) matrix is `PASS` (the task completed) or `FAIL`, because a rubric score can average away a condition in which the product is unusable and a completion ledger cannot. Four identity elements no sibling carries together: a **declared denominator** (the Critical Task Set + Condition Set are ratified *before* the run, and the pairwise-reduced matrix records its dropped cells — coverage chosen after seeing results is not coverage), **adversarial conditions rather than personas** (`runway`/`restyle` ask how a surface *feels*; crucible asks whether the task *finishes* under a degraded environment), **content reality as a first-class axis** (empty state · 10k-row overflow · missing asset · maximum-length label · RTL · longest localized string, driven by generated `mint` fixtures), and an **independent full-matrix re-run** at the gate — not just the remediated cells, because a remediation that trades one condition for another has moved the hole, not the floor. A task that fails under *ideal* conditions exits at Phase 2 to `bug` by contract. Named **Operability Proof**; every open cell is named with `wont-fix`/`needs-redesign`/`needs-platform-support` and an owner — a pass rate without its failing-cell list is forbidden by §2 and §7. Checkpoint-resume (`crucible resume`). `_common/ADVERSARIAL_REFUTATION.md` is deliberately `N/A`: the oracle is binary and reproducible, so the fresh-executor re-run *is* the refutation. 16-34 agents × ≤3 cycles, 5-11× cost. **Always confirm** (intentional parity with runway/summit). Distinct from `runway` (ceiling), `restyle` (standard bar), `canon` skill (standards conformance is one *axis* here), `siege` skill (the system, not the interface), `palette`/`voyager` direct (one fix / suite authoring).

**Chain template:**
`Phase 0 Framing ★confirm-before-launch (unconditional; surface + task-set size + condition breadth + reduced cell count + envelope + cheaper-path → palette/restyle) → 1 Declare ★contract-level (Echo ‖ Palette ‖ Pulse? → CRITICAL TASK SET 3-5 with observable success definitions + CONDITION SET across sensory · motor · cognitive/context · environment · content reality → ✓ratify → denominator freezes) → 1.5 Matrix Reduction ★contract-level (Matrix[pairwise minimum covering set] → reduced matrix + explicit dropped-cell record) → 2 Baseline (Voyager+Echo under IDEAL conditions; any FAIL exits → `bug`) → 3 Trial ⟲{ execute cells ‖ by axis (Palette[screen-reader-only] ‖ Canon[WCAG 1.4.10/1.4.11 mechanical] ‖ Echo[low-vision 200-400% zoom / first-run / interrupted / non-native] ‖ Voyager[keyboard-only / throttled / offline mid-action / viewport extremes] ‖ Mint→Voyager/Pixel[content-reality fixtures]) → FAILURE LEDGER → remediate (Artisan ‖ Palette ‖ Prose ‖ Flow ‖ Muse ‖ Polyglot?) → re-run failed cells }⟲ loop ≤3 cycles (default 3): ACCEPT (zero open critical cells ∧ zero regressions) | diminishing-returns (a cycle closed no new cell) | cap-reached | BLOCK → 4 Floor Gate (INDEPENDENT full-matrix re-run, fresh executors, no Phase 3 history — regressions reported as loudly as open cells) → 5 Deliver (Operability Proof + Guardian)`

## silhouette

**Distinction proof for a product surface** — strip the logo and measure whether anyone can still tell it is yours. Fills the blind spot a craft tournament cannot see: `runway` will happily push a screen to `all dims = 3` that is genuinely well-made *and* indistinguishable from four competitors, because nothing in the roster asks whether it is **ours**. Four identity elements: a **pre-committed Sameness Ledger** (a blind panel enumerates the category's ordinary design moves *before seeing our surface* — `eureka`'s `OBVIOUS`-test discipline, so distinctiveness cannot be claimed in hindsight), an **inverted-polarity visual sweep** (prior art researched to *avoid*, and the competitor set doubles as the blind-test distractor pool), the **Blind Recognition Test** as the oracle (wordmark, product name, naming copy **and brand-unique colour** stripped; our surface mixed with K ≥ 3 competitors before a fresh, engine-diverse panel; attribution rate measured against chance 1/(K+1) with the threshold **pre-declared at Phase 1 and immutable** — lowering it after seeing the result would convert the oracle into a formality), and **distinctiveness that must be free** (a11y ≥ baseline ∧ task friction ≤ baseline is a hard in-loop constraint, so the recipe cannot succeed by making the product strange; every surviving move must additionally **derive from a named brand truth** at the Phase 4 derivation check, or it is stripped and re-measured). Every reported rate carries its K and chance baseline. `BLOCK (convention-locked)` is a legitimate delivery — the honest finding that distinctiveness must come from voice, motion, content, or mechanism rather than layout, handed off to `hallmark`/`prose`/`flow`/`eureka`. Named **Distinction Dossier**; checkpoint-resume (`silhouette resume` — the pre-committed ledger is **never** regenerated after a candidate exists). 14-30 agents × ≤3 cycles, 5-9× cost. **Always confirm.** Its Phase 2 can also run **inside** `runway` as an added rubric dimension (use that form when a surface is being created; the standalone run additionally produces the reusable Sameness Ledger). Distinct from `hallmark` (creates the identity — no settled brand → hallmark first), `runway` (craft ceiling), `restyle` (standard bar), `compete` skill (research only), `eureka` (mechanism novelty, same pre-commit discipline), `crucible` (operability).

**Chain template:**
`Phase 0 Framing ★confirm-before-launch (unconditional; surface + category + K + proposed threshold + envelope + cheaper-path → runway/restyle) → 1 Pre-commit ★contract-level (BLIND default-move panel: Vision ‖ Muse ‖ Palette given the CATEGORY ONLY, never our surface → SAMENESS LEDGER frozen and timestamped + DISTINCTION CONTRACT: category boundary · K ≥ 3 · pass threshold vs chance 1/(K+1) · the brand truths moves must derive from → ✓ratify) → 1.5 Sweep ★contract-level (Compete ‖ Vector?[capture] ‖ Frame? per reference/research-grounding.md, polarity INVERTED → COMPETITOR SET cited + observed rate per pre-committed move → ✓ratify pool → denominator freezes) → 2 Measure (a: BLIND RECOGNITION TEST — branding + brand-unique colour stripped, randomized, fresh engine-diverse panel that has not seen the ledger → attribution rate vs chance; b: SAMENESS SCORE; c: Palette[a11y] + Echo[friction] baselines captured) → 3 Diverge ⟲{ Vision[direction DERIVED from a named brand truth] → Muse ‖ Artisan ‖ Flow?[motion signature] ‖ Ink?[icon/illustration signature] ‖ Prose?[voice] → re-measure with a FRESH panel + sameness score → HARD CONSTRAINT CHECK (Palette a11y ≥ baseline + Echo friction ≤ baseline + Radar no-regression; any gain bought with friction is REVERTED and logged "distinctive but not free") }⟲ loop ≤3 cycles (default 3): ACCEPT | diminishing-returns (Δ < 10pp) | cap-reached | BLOCK (convention-locked) → 4 Attribution Gate (a: FRESH-panel blind test ≥ pre-declared threshold, no prior rounds, no ledger; b: DERIVATION CHECK plan-tier — a move tracing to nothing is decoration, stripped and re-measured) → 5 Deliver (Distinction Dossier + Guardian)`

## lattice

**Design-system coherence proof (steady state)** — `rebrand` proves the completeness of a *brand change*; `lattice` proves the completeness of *system conformance* with no identity change at all: the drift that accumulates silently because every individual deviation is defensible in isolation and the aggregate is a product that looks assembled by five teams. Inherits `migrate`'s three non-negotiables verbatim (freeze the denominator first · prove residue don't trust the counter · delete only after the proof) and adds two things neither `migrate` nor `rebrand` needs: a **three-way deviation classification** — `residue` (a raw value with a token equivalent → the *surface* is wrong) / `gap` (no token or component exists → the *system* is wrong and gets extended, rather than the deviation force-fitted to the nearest wrong token) / `justified` (intentional, with a **recorded reason and owner**, preserved in the report rather than erased — an undocumented exception is the defect, not an exception per se) — and **appearance parity as the safety oracle** per `_common/DIFFERENTIAL_PARITY.md`: swapping a raw value for a token must not change what renders, so a "conformance fix" that shifts a layout by 2px is caught inside the loop, reverted, and re-classified as a `gap`. Classification is model-judged, not purely mechanical, because semantic misuse (`--danger` used as an accent) is invisible to a grep. **Precondition:** a system of record must exist (tokens / component library / Hallmark Charter) — none → route to `muse`/`vitrine` first; lattice never invents the system mid-sweep, the same rule that sends a brandless `rebrand` to `hallmark`. Closes with a **Drift Sentinel** handoff — the scan that produced the proof becomes a `latch` CI/pre-commit check so the proof does not decay. Named **Coherence Proof**; checkpoint-resume (`lattice resume` — the frozen inventory is never re-enumerated, since that is how a denominator silently shrinks). 10-22 agents, 3-7× cost. **Ask First** on big-bang / 10+ files (intentional parity with rebrand/migrate: once at launch, and again before the destructive cut). Distinct from `rebrand` (identity migration), `muse`/`vitrine` direct (design / catalog the system), `restyle`/`runway` (how it looks), `anneal` (code design), `sweep` (dead code), `migrate` (technical change), `chorus` (between platforms).

**Chain template:**
`Phase 0 Precondition + Framing ★Ask First (strategy + 10+ files, once at launch; no system of record → stop, route to muse/vitrine) → 1 Inventory (Lens[every UI surface + every style-bearing declaration: components, pages, stylesheets, inline styles, theme files, email templates, chart palettes, icon sets] ‖ Grove? ‖ Ripple[blast radius] → FROZEN INVENTORY, never re-enumerated) → 2 Scan ‖ per batch (Muse[token conformance] ‖ Vitrine?[component conformance] ‖ Zen?[duplication]) → DEVIATION LEDGER classified residue / gap / justified → ✓user ratifies the `gap` and `justified` classes ★contract-level (mechanical residue needs none) → 3 Reconcile ⟲{ gap → Muse[extend the system, versioned] then replace · residue → Artisan/Muse[token/component replacement] · justified → record reason + owner, surface unchanged → APPEARANCE PARITY (Voyager[visual regression within declared tolerance] + Radar[no-regression] + Palette[a11y ≥ baseline]); a fix that changes what renders is a DEFECT → revert + re-classify as gap }⟲ loop ≤3 cycles (default 3): ACCEPT | diminishing-returns | cap-reached | BLOCK (gaps outnumber residue → muse/hallmark) → 4 RESIDUE-GATE (INDEPENDENT re-scan of the FULL frozen inventory, fresh scanners, looped UNTIL DRY = 2× consecutive zero; completeness never read off the forward counter) → 5 Decommission ★Ask First (orphaned one-offs, duplicate tokens, dead theme entries — gated on the Phase 4 proof) → 6 Deliver (Coherence Proof + Latch?[Drift Sentinel CI check] + Guardian)`

Read: `reference/lattice-recipe.md`, `reference/migrate-recipe.md`, `reference/rebrand-recipe.md`, `_common/DIFFERENTIAL_PARITY.md`.

## chorus

**Cross-platform coherence proof** — prove that each platform build is **idiomatic to its own platform** *and* **recognizably the same product**, simultaneously. The two halves pull against each other, and every cross-platform failure is a miscategorization of one property as the other: a web layout shipped on iOS (idiom lost), or terminology and task flow diverging per platform (kinship lost). Four identity elements: the **Invariant/Variant Contract** ratified before any measurement (invariant = information architecture · terminology · task-flow order and step count · brand tokens · data/state semantics · permission *outcomes* · error meanings; variant = navigation paradigm · gesture vocabulary · system controls · typographic defaults · motion physics · permission *flow* · platform affordances — almost every cross-platform argument is really a disagreement about which list an item belongs to, and the contract settles it once); a **two-sided gate over one oracle** (the **Idiom Gate** and the **Kinship Gate** are two measurements of the same contract, so a fix that raises one by lowering the other is *rejected and escalated to the contract*, never resolved by whichever gate the fixer was optimizing); **learned transfer as evidence** (kinship is not "they look similar" — a persona who completes the task on platform A must complete it on B **first try**, cold, with the friction delta recorded); and **idiom measured against published systems** (Apple HIG / Material 3 as Tier-2 sources per `_common/PROPORTION_AND_SPACING.md` §1 — "feels native" is never a pass criterion, and a violation names the guideline it violates). One user-ratified **contract amendment** is permitted when an item provably cannot satisfy both gates as classified — refused when it is a convenience (moving "terminology" to `variant` because translating is hard); a second conflict exits `BLOCK (contract-conflict)`, because at that point the cross-platform premise is the problem, not the implementation. Both gates are reported **per platform, never aggregated** — "83% coherent" hides which platform is the outlier, the only actionable fact. Named **Chorus Attestation**; checkpoint-resume (`chorus resume`; a fresh kinship panel each round, since a stale one measures memory). Precondition: ≥2 platforms with a shared surface. 14-30 agents × ≤3 cycles, 5-10× cost. **Always confirm.** Distinct from `port` skill (plans the port — `port`→`chorus` is a plan→prove pair), `native`/`MOBILE_NATIVE` (builds one platform), `lattice` (within one platform's system; compose `lattice` ×N then `chorus`), `rebrand` (brand change across touchpoints), `crucible` (conditions, not platforms), `runway` (one surface's ceiling).

**Chain template:**
`Phase 0 Framing ★confirm-before-launch (unconditional; precondition ≥2 platforms sharing a surface → else native/restyle; platform set + flows + both thresholds + envelope + cheaper-path → port/native) → 1 Contract ★contract-level (Magi ‖ Port? ‖ Vision classify every relevant property onto exactly one list: INVARIANT [IA · terminology · task-flow order/step count · brand tokens · data & state semantics · permission OUTCOMES · error meanings · pricing presentation] vs VARIANT [navigation paradigm · gestures · system controls · type defaults & dynamic type · motion physics · permission FLOW · platform affordances]; both gate thresholds declared → ✓ratify → contract freezes, ≤1 amendment) → 2 Audit ‖ one branch per platform per _common/PARALLEL.md (Native/Port?[platform context] ‖ Canon[HIG / Material 3, cited] ‖ Palette[Dynamic Type / VoiceOver / TalkBack] ‖ Echo[platform-native persona] ‖ Lens[implementation reality]) → 3 Measure — two-sided gate, one oracle (a: IDIOM GATE per platform, each variant property scored against its published system WITH A CITATION; b: KINSHIP GATE = blind same-product attribution by a fresh engine-diverse panel + LEARNED TRANSFER first-try completion A→B and B→A with friction deltas; c: INVARIANT DIFF compared literally — terminology table, step count, IA tree) → 4 Reconcile ⟲{ fix per platform (Native ‖ Artisan ‖ Prose[terminology] ‖ Muse[shared tokens] ‖ Flow) → RE-MEASURE BOTH GATES → CONFLICT RULE: a fix raising one gate and lowering the other is REJECTED and escalated to the contract as a candidate amendment → per-platform regression (Radar + Voyager/Snap? + Palette a11y ≥ baseline) }⟲ loop ≤3 cycles (default 3): ACCEPT (both gates pass, no invariant differs) | diminishing-returns | cap-reached | BLOCK (contract-conflict) → 5 Deliver (Chorus Attestation + Guardian per platform)`

## assay

**Experimental proof of design claims (code / architecture)** — the code-design member of the Quality-Max family, and the answer to a question that has never had an oracle: *is this a good design?* Today it is answered with proxies — coupling metrics, complexity scores, review opinions — and every one of those is a **prediction** about how the code behaves under change, removal, simplification, or rule-checking, with the experiment never run. Assay runs it. Four identity elements: the **Design Claim Ledger** (claims harvested from ADRs, architecture docs, and stated conventions, but also from **what the code implicitly claims** — a `domain/` directory claims independence, a plugin seam claims extensibility — and from the roadmap, where planned work claims "this will be cheap to add"; `anneal` hunts *weaknesses*, assay hunts *claims*, which is why they compose rather than overlap); **four instruments, one ledger** (`ADD` · `SUBTRACT` · `REWRITE` · `ASSERT`, assigned **mechanically** from claim type, because instrument choice is exactly where a design proof would otherwise become a design opinion); the **Adequacy Gate** (Phase 0.5 — every instrument reads the test suite as its sensor, so a zero-diff removal means "unnecessary" *only* on an element the suite exercises; otherwise it means **`untested`**, a different verdict, and conflating them is how a design proof produces a dangerous deletion; a scope supporting no instrument at all exits `BLOCK (oracle-inadequate)` and ships a **blind-spot map**, which is a legitimate delivery and arguably the most useful answer the recipe can give); and **refuted-is-a-success** (the oracle counts *unresolved* claims, not unfavorable ones — discovering that a design's central claim is false is the recipe working; the only failure state is "we still do not know"). Instrument discipline: ADD rehearsal implementations are **discarded by contract** with an attestation in the report (they were written to be *measured*, under no review against no acceptance criteria — carrying one forward is the recipe's most tempting contract violation); the REWRITE panel is **pre-committed, blind, and engine-diverse**, so "nobody could simplify it" is a reproduction result rather than a consensus (`eureka`'s ordinary-move discipline); ASSERT may amend the **rule** (`constraint-gap`) rather than the code, and preserves `justified` exceptions with a reason and owner (inherited from `lattice`). `apply=true` is **opt-in and never inferred** — proving a claim false is not authorization to act on it; Phase 5 applies only changes the experiment itself proved safe, behind a second confirm and four preconditions. Named **Design Proof**; checkpoint-resume (`assay resume` — the Adequacy results and the frozen ledger are never regenerated). 24-55 agents, 8-16× cost. **Always confirm** with a declared budget envelope. Distinct from `anneal` (discover + fix — the measure→fix pair, §10 of its reference), `refactor` (known restructure), `acceptance`/`summit` (merge-scoped), `ripple` (predicts without implementing), `void`/`trim` (**judged** vs **experimented**), `siege`/`radar` (assay's sensors, and its remedy on `BLOCK`), `attest`/`pdm` (conformance to a *written* spec), `lattice` (same ASSERT shape, visual denominator).

**Chain template:**
`Phase 0 Framing ★confirm-before-launch (unconditional; scope + claim cap N + instrument mix + BUDGET ENVELOPE + apply mode + cheaper-path → anneal when the ask is "find and fix") → 0.5 Adequacy Gate (Siege[mutation on candidate elements] ‖ Radar[behavioral coverage map] → per-element ADEQUATE/BLIND ranked by blast radius; no element adequate → EXIT BLOCK (oracle-inadequate) shipping the blind-spot map + radar/siege handoff; partial → instruments restricted, BLIND elements recorded oracle-limited) → 1 Claim Harvest ★contract-level (Atlas[layering/boundaries/dependency direction] ‖ Lens[what the structure implicitly claims] ‖ Grove? ‖ Trail[what the history implies] ‖ doc sweep[ADR/README/conventions] ‖ roadmap → DESIGN CLAIM LEDGER: id/claim/source/type/blast-radius/load-bearing → top-N by blast radius → ✓ratify → denominator freezes, deferred claims recorded) → 2 Instrument Assignment (mechanical by claim type: change-cost → ADD · necessity → SUBTRACT · complexity → REWRITE · rule → ASSERT; no matching instrument → recorded `instrument-limited`, never adjudicated by opinion) → 3 Experiment ‖ pipeline per claim, no barrier { ADD: 3-6 real changes each implemented by an independent agent in a THROWAWAY worktree (isolation: worktree) → files touched · layers crossed · locality · unrelated-test breakage · turns → implementations DISCARDED · SUBTRACT ★Ask First: remove on a throwaway branch → build + suite + behavioral diff per _common/DIFFERENTIAL_PARITY.md → zero diff ∧ ADEQUATE = unnecessary / zero diff ∧ BLIND = UNTESTED / diff present = necessary, and the failing test IS the recorded reason · REWRITE: pre-committed engine-diverse blind panel ×3 attempts a simpler implementation passing the IDENTICAL suite → any success = accidental complexity (proven by construction) / all fail = essential (evidenced) · ASSERT: claim compiled into an EXECUTABLE fitness function → full-scope scan → violation / constraint-gap (amend the RULE) / justified (reason + owner) → independent re-scan UNTIL DRY (2× zero) }; ## clone

**Faithful product reproduction** — reverse-engineer an *existing* product's observable surface and rebuild it as a complete copy, **verified by differential parity** against a captured baseline (not assertion). The black-box analog of `transmute`: where transmute extracts its oracle *from your own source*, clone captures the oracle by *observing an external product* (UI / behavior / features / data shape / assets). **Platform-agnostic**: `target_type` ∈ live-web | **desktop** (macOS/Win/Linux GUI) | mobile | has-source | api — same Parity Map, capture mechanism varies (web=Vector/Voyager, desktop=Hearth `automate`/external UI-automation harness). Two principles: **capture-from-evidence** (every reproduced screen is grounded in a captured artifact, never memory) and **fidelity-over-faith** (the copy is diffed against the baseline). Four integrity gates: **Rights** (Phase 0.2, Ask First — authorization basis + ToS/automation posture + PII handling + recreate-never-reuse for marks; an unsupportable basis stops the run), **Capture Completeness** (every screen/state/flow), **Provenance & Drift** (baseline is a stamped snapshot; re-check before SHIP), **Differential Parity engine** (explicit per-dimension comparators + non-determinism canonicalization, shared discipline with transmute §3a). Parity spans **six dimensions** — visual · behavioral · feature · data/API · asset · **performance** (declared envelope, like-for-like replay). Distinct from `transmute` (own-source rewrite) / `migrate` (own-system completeness) / `PORTING` (web→native) / `pixel` (single mockup) / `feature` (net-new inspired design). Opens with an **interactive Stack Dialogue** (Phase 0.1, contract-level — AUTORUN cannot skip) that locks the target rebuild stack (per layer, with stack-vs-fidelity tradeoffs explicit) into a Stack Decision Record before capture/build; `stack=` pre-supplies it. Strategy: extract-and-rebuild (default) ‖ scaffold-from-source ‖ incremental-clone ‖ big-bang. Emits a **Clone Handoff Packet** (SDR + parity harness + rights record + coverage gaps + parity ceilings) downstream recipes re-run before shipping any later change. 9-27 agents. **Ask First at the Rights Gate; confirm before big-bang full clone.**

**Chain template:**
`Phase 0 Framing (target_type + provenance stamp + robustness obstacles) → 0.1 Stack Dialogue (INTERACTIVE, contract-level — AUTORUN cannot skip: fingerprint original stack ‖ Lens/Atlas read user repo/constraints → layered AskUserQuestion runtime→frontend→styling→state→backend→data→build→deploy, surface stack-vs-fidelity tradeoffs → lock Stack Decision Record; `stack=` confirms not explores) → 0.5 Research Sweep (deep-research[+Compete?] → cited Evidence Ledger: T1 docs/design-system/API-ref/changelog → T4 community; reference/research-grounding.md → completeness denominator + exact values + version/drift; research-first, capture-authoritative) → 1 Capture (Vector/Voyager crawl+screenshot+network | Hearth `automate` desktop ‖ Frame/Pixel design-extract ‖ Lens? ‖ Schema? ‖ Echo/Trace? ‖ PDM/Lens feature-inventory ‖ Ink/Pixel? asset-extract) → 2 Spec+Baseline (Scribe/Accord spec → stamped parity baseline + Capture Completeness Gate + Provenance & Drift Gate) → 3 Architect (Magi capture-strategy gate + Parity Map; Atlas?/Muse?) → 4 Rebuild (Forge→Artisan/Builder + Pixel pixel-accurate +gateway/schema?+flow?; rally COMPETE for fidelity-critical screens) → 5 Parity Verify (Pixel/Voyager visual ‖ Radar/Voyager behavioral ‖ Attest feature ‖ Pixel/Frame asset ‖ judge fidelity; drift re-check; loop ≤3 cycles) → 6 Ship (Guardian + Fidelity Report incl. provenance + drift status)`

Read: `reference/clone-recipe.md`.

## fuse

**Multi-source product synthesis** — the synthesis extension of `clone`. Where `clone` reproduces **one** product faithfully against a single baseline, `fuse` captures **two or more** products (clone's full capture/provenance/parity machinery, run per source) and **synthesizes them into one new product**: adopting selected elements from each source, merging overlapping ones, and adding net-new connective tissue. The deliverable is **intentionally not a faithful copy of any single source**, so clone's single-baseline oracle no longer applies — `fuse` adds the three things clone cannot express: a **Fusion Map** (assigns every element of the new product a provenance `{adopt-A|adopt-B|merge|net-new|drop}` + resolution rationale + oracle), a **dual/selective oracle** (adopted elements → differential parity vs *that source's* baseline; merged/net-new → spec+AC conformance — never confused), and a **Coherence Gate** (proves the result is one product — one visual language / interaction grammar / terminology / data model — not a Frankenstein patchwork). Conflicts between sources (two nav models, two schemas for "the same" entity) are resolved in a **Conflict Ledger** (Magi-arbitrated against the Fusion Thesis). Multi-source IP/trade-dress posture is recorded per adopted element. `sources=2..N`, mixed `target_type` allowed. Distinct from `clone` (one source, fidelity *is* the goal), `feature`/`apex` (net-new, only inspired — no captured baselines), `migrate` (own-system consolidation), `transmute` (own-source rewrite). Pair `spec → fuse` when *which* elements to take from each source is itself unsettled. 12-32 agents, high cost. **Confirm before big-bang full fusion OR sources ≥ 3.**

**Chain template:**
`Phase 0 Framing (sources + per target_type + new-product stack + Fusion Thesis + per-source provenance stamps) → 1 Capture ∥ (clone Phase 0.5 research sweep + Phase 1 per source → per-source Evidence Ledger + one stamped baseline each, research+coverage scoped to the adopted slice; +1 fusion-level Compete sweep → Thesis/Conflict rationale; reference/research-grounding.md) → 2 Fusion Map+Spec (Spark synthesis ‖ Magi conflict-arbitration → Fusion Map + Conflict Ledger + Accord/Scribe L3 ACs for merge/net-new → Fusion Map Gate + Selective-Oracle Gate + Coherence Contract + IP/Trade-Dress Gate) → 3 Architect (Magi strategy + Atlas unified arch + Muse reconcile tokens + Schema?/Gateway? reconcile data/API) → 4 Build (adopted=Pixel/Builder clone-discipline ‖ merged/net-new=Forge→Artisan/Builder feature-discipline; rally COMPETE for fidelity-critical + hard merges) → 5 Dual Verify ∥ (selective parity vs source baseline ‖ Attest spec-conformance ‖ Coherence Gate visual/interaction/conceptual/data ‖ judge synthesis review; per-source drift re-check; Fusion-Map coverage re-check; loop ≤3 cycles) → 6 Ship (Guardian + Fusion Report)`

## graft

**Concept transplant for innovation** — the extension of `fuse` and the **inverse of `clone` on the fidelity axis**. Where `clone`/`fuse` reproduce *observable surfaces* by parity, `graft` takes **your current owned product** as the *host* (white-box, mapped from source — not captured) and extracts a specific reference product's (the *donor*) important **concepts** — its load-bearing principles/mechanisms, abstracted *away* from the donor's surface — then transplants and adapts them onto the host to produce a **genuinely innovative** product. It **explicitly rejects surface copying** (the opposite of clone): a graft that copies the donor's chrome while missing the idea that made it work has failed. Verified by a **triple oracle** held on *every* graft: **concept-fidelity** (the donor concept's mechanism/effect reproduced, re-expressed originally in the host's surface — Attest+judge, high donor-resemblance is a *smell*) ∧ **host-integrity** (the living product's existing-behavior regression net stays 100% green + declared invariants hold — Radar+Ripple) ∧ **Innovation Gate** (emergent novelty neither host nor donor had, surviving adversarial "this is just a bolt-on/gimmick" refutation + felt-novelty via Echo + defensibility via Compete — borrowing `killer`'s moat/refutation discipline). A graft that is concept-faithful and host-safe but fails the Innovation Gate is delivered honestly as "a feature, not an innovation." Core artifact: **Graft Map** (per donor concept → `adapt`|`hybridize`|`invert`|`reject` + host attachment point + adaptation + per-graft innovation thesis + invariants respected); plus a **Host-Invariant Contract** (value-path/workflow/data/contract non-negotiables) and a per-graft **originality posture** (default: re-implement the idea originally — concept-level transplant is structurally lower IP-risk than surface reproduction). Flux is core (concept distillation + hybridize/invert novelty moves), not optional. Ships behind a feature flag with adoption KPI + kill criterion (killer-style) unless waived at Phase 0. `host=1, donors=1..N`. Distinct from `fuse` (peer external sources, surface synthesis, no owned host), `clone` (surface reproduction), `kaizen` (metric PDCA, no external concept/novelty bar), `feature` (additive, no concept extraction/innovation gate), `killer` (verdict only — pair `killer → graft`). 10-28 agents. **Confirm when invasive to host core OR shipping without a flag.**

**Chain template:**
`Phase 0 Framing (host + donor(s) + Host Invariants + Innovation Thesis) → 1 Ground ∥ (HOST: Lens/Atlas map + PDM inventory + Radar freeze regression net ‖ DONOR: deep-research concept-rationale sweep first [reference/research-grounding.md] → observe→Flux+Magi distill to Concept Catalog/essence ‖ host-domain/competitive sweep → Innovation Thesis) → 2 Graft Map+Spec (Flux novelty moves → Magi select [subtraction] → Graft Map + Accord/Scribe concept-fidelity spec+L3 ACs + Ripple blast radius → Graft Map Gate + Triple-Oracle Gate + Host-Invariant Contract + Originality Posture) → 3 Architect (Magi strategy + Atlas integrate-into-host + Ripple ‖ Omen pre-mortem + Muse? re-express in host tokens) → 4 Build (Forge spike novel graft first → Artisan/Builder onto host under isolation:worktree, regression net stays green; rally COMPETE on high-innovation grafts) → 5 Verify ∥ (concept-fidelity Attest/judge ‖ host-integrity Radar/Ripple ‖ Innovation Gate judge+refute×2-3+Echo+Compete+Magi Go/No-Go; coverage re-check; loop ≤3 cycles) → 6 Ship (Guardian + Graft Report + flag[KPI+kill])`

Read: `reference/graft-recipe.md`.

## eureka

**Novelty-proven invention** — the origination member of the Reproduce/Synthesize/Invent family, and the only recipe whose oracle is *absence*: where `clone` proves a copy matches its source and `graft` proves a transplanted concept took hold, `eureka` proves its mechanism **has no source**. Five identity elements no sibling carries together: **contradiction extraction** (Phase 1 names the trade-off the domain accepts as a law — "<better X> requires <worse Y>"; no nameable contradiction → it is a task, not an invention, and the recipe routes out), **Prior-Art Ledger** (a cited, tiered sweep per `reference/research-grounding.md` with **inverted polarity** — clone researches to reproduce, wish to reach, eureka to *avoid* — becoming the novelty denominator, with **papers/standards/inspectable implementations outranking vendor claims** and adjacent-industry search mandatory), **failure archaeology** (for every abandoned prior attempt, *why* it failed — physics/economics/adoption/timing/tech-readiness; these become Phase 2 constraints and Phase 4 value tests, so a candidate cannot repeat a known failure), **falsification-first reduction to practice** (the minimum artifact demonstrating the mechanism, built to be *killed*, with its success criterion declared before the run and judged by Radar rather than its builder — the line between an invention and an idea), the **tetrad gate** (novelty · value · feasibility · defensibility), and **sacrifice accounting** — the third definitional condition: an invention's trade-off must be **gone, not relocated**, so the Phase 4 **Sacrifice Ledger** gate accounts every axis a real system pays on (cost · latency · complexity · reliability · security · privacy · user effort · ops burden · **other stakeholders** · **future debt/lock-in**) and returns `DISSOLVED` | `DISPLACED-DECLARED` (passes — the cost landed on an axis the Phase 1 constraint budget declared free, and the move is stated as part of the mechanism, because generator ③'s constraint inversion is built on exactly this) | `DISPLACED-HIDDEN` (**killed** — an undeclared payment, or one the budget forbade) | `FREE-LUNCH` (does *not* pass on sight: one extra skeptic is briefed only to "name the axis we failed to count", and only a failed search promotes it). It is a **gate, not a fifth axis**, because scoring completeness 0-3 would let a partially-accounted candidate average past a hole in its own ledger. Rights, licensing and patentability are **out of scope at every phase** — the frame is engineering novelty, not law, and there is deliberately no rights axis or side-check; a user who wants legal review routes to `clause` separately. Six structurally-different generators diverge cross-engine (contradiction-dissolution · cross-domain transplant · constraint inversion · first-principles rebuild · scaling-law extrapolation · latent-need inversion) — six heuristics, not six prompts, because invention is the task where model priors are the binding constraint. The Novelty Gate **kills collisions with their citations**, and a candidate that cannot state how it differs from its nearest prior art is killed as an unexamined idea; a candidate whose delta *is* stateable but is a **routine move** — a standard combination, a like-for-like substitution, a parameter/scale change — is killed `OBVIOUS` by a **blind ordinary-move panel** that pre-commits its proposals at Phase 2 from the ledger alone, so ordinariness is decided by reproduction rather than by hindsight. Cross-domain candidates are judged as **composites** (foreign mechanism + local adaptation) against a **domain-scoped** denominator: a foreign entry sets the `OBVIOUS` bar, never an automatic `COLLISION`, and a routine import routes to `graft` instead. Evaluators are **prior-art-anchored calibrated**: the nearest prior art must score novelty 0 and feasibility 3, or the evaluator is re-prompted. Ceiling ACCEPT = all 5 dims (novelty · value · feasibility · defensibility · **enablement**) = 3; enablement is scored because an invention only its inventor can build is not transferable. **Salvage Routing** is contract-level, because this is the roster's most likely producer of valuable things that miss its own bar: a `COLLISION` means someone already built it (so the mechanism *works* — route to `graft`/`feature` with the citation as reference implementation), an `OBVIOUS` means a cheap improvement nobody bothered to make (`kaizen`/`optimize`), a `DISPLACED-HIDDEN` means a real change whose price was found (`feature`/`kaizen` **with the Sacrifice Ledger attached as declared cost**, or `magi` when the trade needs an owner), a VALUE fail may still be a bet (`killer`/`compete`), a FEASIBILITY fail carries a **dated re-check trigger** (the constraint whose price change revives it — generator ⑤ run backwards), a DEFENSIBILITY fail is parity work worth building (`spec`→`apex`, never sold internally as a moat), and ENABLEMENT ≤2 routes to `scribe`/`quill` until it is transferable. Every kill and non-`ACCEPT` exit therefore carries `route:<recipe>` + handover or an explicit `discard(<reason>)` — `salvage` is a required Idea Ledger field, ≤3 routes ranked by expected value, **recommendation-only** (auto-spawning a salvage recipe would spend an envelope nobody approved; `ship=true` is the sole continuation this recipe pays for). Distinct from the mid-run `WRONG-RECIPE` pivot detector, which fires *before* the cost is spent rather than after. A **`BLOCK (prior-art saturation)` run still ships its Invention Dossier** — "everything tried in this space, why each failed, and why the obvious next move is not new" is a real answer to "invent something," and forcing a weak invention instead would be the dishonest exit. The **idea field is an interim deliverable, not just a dossier section**: an **Idea Ledger** is emitted mid-run — v1 raw at Phase 2 exit (dedup *shown*, not silently applied), v2 adjudicated at Phase 3 exit (each verdict with its evidence), v3 appended if the one re-ideation fires — informational and never a gate, so a run cancelled mid-way has already delivered every mechanism it generated. Each emission carries a **Pivot Advisory** when a named detector fires on artifacts already produced — `CONTRADICTION-DRIFT` (the generators keep dissolving a *neighboring* trade-off that scores higher) · `FRAMING-IS-THE-ORDINARY-MOVE` (the Ordinary-Move Set covers the whole field, so the framing itself is the routine one) · `DENOMINATOR-CLUSTER` (every collision cites one cluster while an unswept adjacent field keeps surfacing) · `ADOPTION-BLIND` (the archaeology's adoption reasons kill every candidate under this framing) · `WRONG-RECIPE` (the best direction is a routine import → `graft`, a known solution → `feature`/`spec`, or a pick-from-candidates verdict → `killer`). Emitting is free and evidence-bound (zero advisories is the normal case); **acting** on one that re-states the frozen contradiction or re-scopes the frozen ledger is a **contract-level confirm AUTORUN cannot skip**, and the budget it draws on is named explicitly — scope widening (research envelope), constraint change (the one re-ideation), or a re-stated contradiction (**a new run under a new envelope**, never a continuation on the old counters). Named **Invention Dossier**; checkpoint-resume (the ledger is never re-swept — a re-swept ledger would silently move the novelty denominator). Distinct from `graft` (transplants a mechanism already proven elsewhere — one of eureka's six generators, not the whole recipe), `fuse` (recombines existing products), `killer` (picks from candidates in hand, no novelty proof, no spike), `spark` (feature ideation inside the known solution space), `gedanken` (reasons, produces no falsifiable artifact), `wish` (maximizes execution of a *known* deliverable). 32-62 agents × ≤3 cycles (+1 re-ideation, sharing the cycle budget), 9-24× cost. **Always confirm** (wish-class parity); **Ask First** on any spike touching real systems. **Three rungs, priced separately** so the cheap question never carries the expensive one's bill: **`depth=scout`** answers *is it new?* alone — Phases 1 → 1.5 → 2′ (3 generators, 2-agent blind panel) → 3, a **Novelty Scout Report** (never "dossier") whose every survivor is labelled `UNPROVEN` with what is missing stated, 11-14 agents, 3-5× cost, **one** confirmation (contradiction + ledger scope ratified together, no launch gate — always-confirm exists because a wish-class run is expensive, and at 3-5× it is not), no loop, no spike, `ACCEPT` unreachable by construction, exits `NOVEL-CANDIDATES` | `SATURATED`, and **mutually exclusive with `ship=true`** (a scout cannot satisfy Ship Gate ①). Promotion to a full run **re-enters at Phase 2 against the frozen ledger** — the sweep is never re-run, the scout panel's proposals top up to the full 3-agent panel with blindness intact, so promotion costs +21-46 agents rather than a fresh 32-62 — scout-then-promote (32-60) never exceeds a full run, which is what makes trying the cheap rung first riskless. It exists because `spark`/`graft`/`feature` are cheaper but **none of them judges novelty**, which left "just check whether this is new" without a proportionate owner. **`eureka ship=true`** is the opt-in end-to-end continuation (never inferred): a **Ship Gate** with five preconditions (`ACCEPT` exit · 0 surviving attacks · ENABLEMENT=3 · spike survived · a *separate* build envelope, second unconditional confirm) freezes the dossier and emits an **Invention Handoff Packet**, then `spec` runs collapsed to validation (the direction was already refuted at Phases 4 and 6) and `apex` builds under a **Novelty Invariant** — the load-bearing delta may not be simplified, deferred, or scoped out, and a final **novelty regression check** by a non-builder verifies the shipped artifact still embodies the claimed mechanism, retracting the claim rather than shipping a generic feature under an invention's name. Any missed precondition ends the run at the dossier with the precondition named. `ship=true` adds +11-30 agents → combined 43-92 agents, 13-33× cost.
